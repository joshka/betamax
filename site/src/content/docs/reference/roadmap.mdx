---
title: Roadmap
description: Planned work on rendering, key encoding, library outputs, and benchmarks.
---

Planned work, in suggested priority order:

1. Extend renderer tests for wide glyphs, combining marks, emoji, and fallback fonts, then fix
   differences from expected terminal output.
1. Pass live terminal mode state to `libghostty-vt::key::Encoder`. Test applications that switch
   cursor-key or keypad modes.
1. Decide whether library callers should receive images, frames, and state snapshots without
   writing files. `Runner::run_artifacts` already returns final terminal state.
1. Consider injectable process, clock, and filesystem interfaces if direct library use grows.
   These would let tests exercise timing and failures without real shells or media files.
1. Add benchmarks for rendering, state compaction, frame decoration, and GIF encoding once their
   behavior settles.
1. Keep MP4/WebM encoding in optional [ffmpeg](../../authoring/outputs/#video-encoding) unless users
   need native encoding. Native support would add codec dependencies and platform tests.
1. Watch for a supported libghostty frame-capture API. The Rust bindings Betamax uses do not
   currently expose one.

See the [repository roadmap](https://github.com/joshka/betamax/blob/main/docs/roadmap.md) for details
and [Differences from VHS](../vhs-differences/) for compatibility and unsupported features.
