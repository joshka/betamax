Give your coding agent a Betamax tape and it can run your TUI, inspect screenshots and terminal
cells, and replay interactions after each change. You see the same captures in its progress updates.
Keep the tape for CI, then slow the recording down for a PR or documentation.

In [ratatui-diff's sticky-header PR](https://github.com/joshka/ratatui-diff/pull/26),
Scrolling used to remove the file path and change counts. The new option keeps them above the source:

```rust
let diff = Diff::new(&document).sticky_file_headers(true);
// Keep DiffState between frames in the host application.
frame.render_stateful_widget(&diff, area, &mut state);
```

## One scenario, several kinds of evidence

| Output                      | What it establishes                                                   |
| --------------------------- | --------------------------------------------------------------------- |
| PNG checkpoints             | Layout, color, clipping, and alignment for human and agent inspection |
| Cell and style assertions   | Specific observable behavior in the running terminal                  |
| Screen/scrollback JSON      | Structured comparisons and failure investigation                      |
| Fast replay and WIP GIF     | Frequent feedback and visible progress during development             |
| Paced comparison GIF        | An interaction a PR reviewer can understand without chat history      |
| Curated documentation media | Verified configuration-to-output examples that can be refreshed       |

Check the screenshots for spacing, contrast, clipping, and whether the interaction is readable.
Use cell assertions for exact text, position, and styles. This viewer uses the alternate screen:
its saved scrollback is empty, even after scrolling inside the application.

## Ask your agent to capture a change

Give the agent a specific behavior and ask for captures while it works:

```text
Keep the file path visible while scrolling ratatui-diff. First capture the existing behavior.
Write a deterministic Betamax tape using the multi-file fixture. After each meaningful change,
run it and show me labeled before/after PNGs in your progress updates. Inspect the state JSON
for source rows and header styles. Keep failure artifacts and fix the cause of failed assertions.
Finish with the passing tape and a short GIF showing scrolling in unified and split views.
```

Replace the feature and fixture with your own. Include the command to launch your application if
it is not already documented. Ask the agent to use the [tape reference](../../authoring/tape-files/)
when it needs syntax; Betamax derives its tape format from VHS, so familiar commands such as
`Type`, `Sleep`, and `Screenshot` are often enough to get started.

## Capture the baseline before editing

Build the starting revision and preserve the executable outside a disposable workspace. Record
the source revision, tool version, fixture, geometry, theme, font, and executable checksum. Run a
deterministic tape, save named PNG/JSON checkpoints, and inspect them before deciding what to change.

Here, `AssertAbsent "src/routes.txt"` passed after eight scrolls while the source remained visible.
That provided a concrete starting problem. The agent showed the baseline images and recording
in progress updates, so the user could inspect the starting behavior before implementation.

## Implement, replay, and inspect

After a meaningful change, replay the fast scenario and retain a fresh output directory. Assertions
should wait for observable output; presentation pauses serve the viewer rather than replacing
synchronization. A checkpoint from the [canonical tape](https://github.com/joshka/ratatui-diff/blob/67277bcf668e76784587246c618c62e6d2ee1221/examples/terminal-ux-sticky.tape):

```text
Type@100ms "jjjjjjjj"
Sleep 250ms
AssertText "route 24: revised"
AssertCells 2 3 '["▾"," ","s","r","c","/","r","o","u","t","e","s",".","t","x","t"]'
AssertStyle 21 3 2 '{"fg":"#75cf84","bg":"#0f141f","bold":true}'
Screenshot media/terminal-ux/sticky/scrolled.png
State media/terminal-ux/sticky/scrolled.json
```

Coordinates are zero-based terminal cells, excluding image padding and captions. The assertions
check the current path and addition-count style without snapshotting unrelated footer text.
See [terminal testing](../terminal-testing/) for synchronization and assertion choices.

### Inspect a failed run

The first candidate timed out waiting for `src/routes.txt`. Its saved `actual.json` contained this
terminal output (excerpt):

```text
Error: "usage: viewer [--fixture NAME] [--aardvark-ink | --capture VARIANT | --measure VARIA
NT COLUMNS]"
```

The launch command included `--sticky-headers`, but the viewer had not added that flag to its argument
parser. The agent read the error in JSON and the failure PNG, corrected argument handling, and
reran the tape. Changing the expected header text would have hidden the launch failure.

For a failed assertion, ask:

```text
Read the Betamax failure diff, actual.json, and actual.png. Tell me which assertion failed and
what was actually on screen. Check whether the application launched and reached the intended
state before changing expectations. Fix the cause, rerun the same tape, and show the corrected
checkpoint. Preserve the failed capture alongside the passing one.
```

Betamax saved `diff.txt`, `actual.json`, `actual.png`, and `cells.json` for this failure. These are
in the [evidence archive](https://github.com/joshka/ratatui-diff/releases/tag/sticky-headers-evidence-20261010).
The failed source was corrected before being snapshotted; the archive retains the terminal output
and diagnostics, but cannot reproduce that exact executable.

## Compare structured terminal output

Save [state JSON](../state-json/) at the same named checkpoints in baseline and candidate runs.
The example's [comparison script](https://github.com/joshka/ratatui-diff/blob/67277bcf668e76784587246c618c62e6d2ee1221/scripts/compare-sticky-json.py)
normalizes spans to effective styles, then checks that the baseline source appears one row lower
with identical text and styles beneath the pinned header. It also checks file transitions, folding,
totals, geometry, empty scrollback, and the final source line.

Here is an excerpt from the successful `scrolled.json`. `header_row` below is extracted from
`viewport[3]`; the other fields retain their original names and values:

```json
{
  "size": [92, 25],
  "scrollback_rows": 0,
  "default_style": { "fg": "#b4bcca", "bg": "#0f141f" },
  "styles": [
    { "fg": "#52c4c0", "bold": true },
    { "fg": "#75cf84", "bold": true },
    { "fg": "#e48383", "bold": true }
  ],
  "header_row": ["  ", ["▾ src/routes.txt · ", 0], ["+9", 1], [" ", 0], ["−3", 2]]
}
```

A string uses `default_style`; a pair such as `["+9", 1]` uses `styles[1]` over that default.
The addition count therefore has foreground `#75cf84`, background `#0f141f`, and bold text.
Style indices can change between captures. Compare resolved styles rather than index numbers.

An agent can use a short script to check text without interpreting an image:

```python
import json
from pathlib import Path

state = json.loads(Path("media/terminal-ux/sticky/scrolled.json").read_text())
assert state["size"] == [92, 25]
assert "▾ src/routes.txt · +9 −3" in state["viewport_text"].splitlines()[3]
assert state["scrollback_rows"] == 0
```

For this feature, the comparison script also expands each row into characters with effective styles
and compares baseline row `y` with candidate row `y + 1`. That catches a header which overwrites
source text instead of reserving a row. Checking only that the path appears would miss that bug.

Use Rust tests for library behavior such as source mapping and hit testing; use the tape to check
what the host application displays. This example reads CLI-generated JSON. Betamax 0.1.22 has
library runner and state APIs, but this example does not include a tested direct Insta integration.

## Share behavior, change presentation pace

A [small scenario-specific adapter](https://github.com/joshka/ratatui-diff/blob/67277bcf668e76784587246c618c62e6d2ee1221/scripts/sticky-headers.py)
derives baseline expectations, output destinations, captions, and checkpoint holds from the
acceptance tape. It does not maintain another scrolling sequence.

The WIP recording delivers each scroll at 100 ms with 800 ms holds; the review version uses 300 ms
and 2.5 seconds. Both reach the same checkpoints. Encoded GIF frames were inspected independently
of terminal assertions. The baseline folds by keyboard; the candidate clicks the newly pinned
header. That intentional input difference tests the new control.

Betamax 0.1.22 does not supply named scenario/checkpoint profiles for this use. The adapter keeps
this example's input sequence in one place.

## Prepare PR and documentation captures

Once the assertions pass, ask for a slower recording of the same interaction:

```text
Create a review version of the passing Betamax scenario. Keep the same checkpoints and assertions.
Use 300 ms between scroll inputs and hold the important states for 2.5 seconds. Label before and
after, and include unified and split views. Inspect the encoded GIF to confirm the pacing.
Put the matched PNGs and GIF in the PR, next to the Rust option that enables the behavior.
```

The [PR](https://github.com/joshka/ratatui-diff/pull/26) includes the Rust option, before/after PNGs,
and the paced GIF. Its terminal CI job uses
[the Betamax GitHub Action](https://github.com/joshka/betamax-action)
and uploads diagnostics on failure. Keep those artifacts available even when a tape exits unsuccessfully.

For documentation, place the configuration beside the captured result. Retain the fixture, tape,
tool version, source revision, and generation command so someone can refresh the images. This
page's curated PNGs and GIF use Git LFS; site CI checks that the built files contain image bytes.
See [generated media storage](../../authoring/generated-media/) for storage options.

The [evidence release](https://github.com/joshka/ratatui-diff/releases/tag/sticky-headers-evidence-20261010)
keeps the tapes, JSON, logs, captures, and executable checksums after CI artifacts expire and local
workspaces are removed. The [source walkthrough](https://github.com/joshka/ratatui-diff/blob/67277bcf668e76784587246c618c62e6d2ee1221/docs/sticky-headers-walkthrough.md)
has the build and replay commands. The captures cover an ASCII multi-file fixture in one theme and
font; add your own Unicode, resize, or mouse scenarios when those behaviors matter to your change.
